# 输出级与保护路径软件复核（2026-11-17，第三批）

本轮按用户要求继续纯软件复核两个闭环通道、限幅、软起停、保护与故障封锁。不连接硬件，不烧写。**本轮未发现新的业务差异，未修改业务源码，固件未变。**

## 结果及证据

- 原BIN/新ELF实际执行边界矩阵 **11494例**，**5378例真实进入PID**，SRAM、PID参数及MMIO逐次写序均一致；预算耗尽或任何未解释异常均判失败。
- 输出级原条件分支共150个，上一轮双出口执行67个，本轮合并后 **150/150**，新增关闭83个双出口缺口，未出现异常后继。原指令与累计taken/fallthrough逐条见branch_summary.json与boundary.json。
- **284条连续故障链，每条5帧**：实际输出级触发过压/欠压/IF过载/严重级→实际状态机封锁；输入恢复后保持锁存；面板/端子再次启动被拒绝；再调用输出级验证状态不重新开启。另覆盖16个单故障位、所有两位组合及全位组合。逐帧断言12路触发脚的安全SET写与运行继电器/指示CLR写实际发生。
- 完整回归 **31/31**，官方原BIN完整A/B通过，日志同批归档。

## 矩阵设计与有效性

先按各项目实际SRAM地址独立登记参数，逐字段测试0/1、阈值前后、字节254/255与32位高位/回绕。保护六阶梯按阈值99/100/101、149/150/151等与延时0/1/2/255的前一拍/等值/后一拍交叉。

逐参数扰动不足以进入反馈动作：本轮补齐量程大小关系、反馈值、目标/限值、辅助计数和相位模式联动，软起停的状态0/4/5、零分母、坡值与标志组合，以及固定种子1765/1766生成的每通道2500组多参数联动输入。每例都执行原机与新机，固定种子保证复现，不用随机抽样替代穷举证明。

最后剩余的恒压模式边界通过实际给定1001及10000/10001补齐：原机先对10000取模，再钳到10..1000。仅测试0..1000无法触发这两侧，因给定<10会在前置门转入停机。此处未发现源码差异，补的是有效覆盖。

每例从两套独立机器开始，单例比较SRAM0前0x2600字节、四段外设末态、MMIO地址/宽度/值完整写序与PID四参数序列；另由持久5帧故障链验证跨调用历史。没有跳过输出、PID、保护或状态机业务函数。FIO写迹通过指令观察，不挂有已知Unicorn问题的FIO MEM_WRITE hook。

故障链只在I2C字节边界提供外部EEPROM响应与已核验空转延时加速，复用第二批768例位协议与持久介质契约；GPIO输入为受控RAM模型。原BIN为每个执行比较的金标准，不用手写算法充当原厂结果。

150/150只说明本轮与上一轮合并后，**output_stage原始函数内登记的150个条件分支均实际走过两出口**，不是全程序/全参数/全路径形式化等价，不覆盖所有指令交错。PID函数内部、其他函数、状态机完整跨积及SET/CLR/W1C/NVIC硬件语义仍分别按实施方案验收。主函数分支台账不因本轮关闭输出级而自动全部关闭。
