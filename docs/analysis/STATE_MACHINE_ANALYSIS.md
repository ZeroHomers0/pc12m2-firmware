# state_machine (0x458C) 拆解报告

> 固件：`LPC1765.bin`（NXP LPC1765 / ARM Cortex-M3，256KB flash @0x00000000）
> 函数：`state_machine` 入口 0x458C，体 0x458C–0xAB47，约 10049 条指令（~26KB）
> 设备：中文界面 **变频电源**（正弦波电源，SINE POWER）

---

## 1. 总体架构：这不是传统"持久状态机"，而是"菜单渲染/事件分发器"

`state_machine(r4)` 接收一个参数 `r4`（序言 `mov r4, r0`），该参数是**当前菜单状态**（哪个屏幕/菜单项被选中）。每次被主循环调用时执行：

```
state_machine(r4 = 菜单状态):
  1. 屏幕超时:  递增 [0x10001748] 计数器; 若 r4>0(有活动) 则清零;
                若计数器 > 0x1388(5000) 则关闭 LCD 控制线(FUN_000007b6(0))
  2. I2C 参数同步: FUN_00001ab8() 每约16轮返回1 → 把4组参数写往 I2C 器件 0xA6
                 (寄存器 0x97/98, 0x99/9A, 0x9B/9C, 0x1D/1E)
  3. out_param 位标志 → 状态码: 读 out_param(0x10001624) 的位 0x1/0x2/0x4/0x8/0x200...
                 映射到 [0x10001740] 状态码(1/2/3...)
  4. 按 r4 分派 → 渲染对应屏幕: 设 mode 字节 + 频率 + 清屏 + 显示中文字符串/数字
```

真正的"状态"由几个 RAM 变量共同构成：
- **`r4`（函数参数）** = 菜单状态（0,1,2,3,4,5,6,0xE,0x16,0x17,0x21）
- **`ui_mode` (0x10001744)** = 当前屏幕指示字节（被设为 0xA/0xC/0x14/0x62…）
- **`cfg_word` (0x10001628)** = 子状态/配置标志
- **`freq_hz` (0x10001FF8)** = 运行频率（50/60Hz）

---

## 2. 菜单状态表（r4）—— 完整版

状态按 r4 分派；0x2/0x16 与 0x3/0x21 各自成对、共用同一处理路径。以下 RAM 地址均已从字面量池解析。

| r4 | 语义 | 关键动作 |
|---|---|---|
| 0x0 | 默认/空闲 | 多处作为比较基线 |
| 0x1 | **频率 60Hz** | mode=0xA；freq_hz=0x3C(60)；显示"60 S" |
| 0x2 / 0x16 | **参数递增**（编码器顺时针） | edit_value[0x100015d8] +=1（钳位 10..1000）；disp_fixed_1dec 显示 `X.X` |
| 0x3 / 0x21 | **参数递减**（编码器逆时针） | edit_value -=1（下限 10）；disp_fixed_1dec 显示 `X.X` |
| 0x4 | 参数编辑入口 | mode=0x14；需 cfg_word==0 且 out_param!=0 |
| 0x5 | **运行** | run_flag[0x10001785]=1；cfg_word=1；显示"运行" @row3,col10 |
| 0x6 | **停机** | run_flag=0；flag_7f[0x1000177f]=1；cfg_word=0；显示"停机" @row3,col10 |
| 0xE | 密码/设置 | mode=0x62；显示"初始参数设置" |
| 0x17 | 运行时间屏幕 | mode=0xC；显示本次/累计运行时间 |

> 0x16/0x21 与 0x2/0x3 共用完全相同的递增/递减代码路径（`cmp r4,#2; cmp r4,#0x16` 落到同一段），
> 差异只在于到达该路径前的其它标志判断（`[0x10001655]` 子状态 / 运行模式字节），
> 因此它们是**同一编辑屏的两种进入方式**，而非独立子菜单。

### 参数编辑核心逻辑（0x52FA–0x541C）

`sub_state = [0x10001655]`，`gain_sel = [0x10001634]`（0 或 1）：

```
sub_state == 0:  out_scaled[0x10001774] = src_value[0x10001788] × 增益 / 1000
                 out_copy[0x100015a8] = src_value
sub_state == 1:  out_d0[0x100015d0] = out_b4[0x100015b4]
sub_state == 2:  编码器编辑 edit_value（状态 0x2/3/0x16/0x21）
                 out_d4[0x100015d4] = edit_value × 增益 / 1000
                 增益 = gain_sel ? [0x10001638] : [0x1000163c]
```

> `edit_value`（10..1000，显示为 `X.X`）就是旋转编码器调整的**输出设定值**（如 `220.0`）。
> `× 增益 / 1000` 换算成实际输出量（DAC 码/PWM 占空比）。增益档 `gain_sel` 配合
> 菜单里的 `恒压/恒流/开环` 三模式，对应三种输出控制方式的缩放系数。

| 0x4D80 | `2.累计运行时间: ` | 状态 0x17 |
| 0x4D9C | `  密码:------` | 状态 0xE |

| 0x4DC8 | `  密码:------   ` | 状态 0xE |

> 0x47E8–0x480C 是一张**运行模式小表**：`停机/运行` + `恒压/恒流/开环`，
> 每项后跟一个 RAM 指针（如 0x47F8→0x10001634）。这印证了设备是
> **恒压/恒流/开环三模式变频电源**，运行/停机由状态 5/6 切换。

## 8. 结论：state_machine 完整语义

`state_machine(r4)` 是一台**恒压/恒流/开环三模式变频电源**的菜单渲染 + 事件分发器：

- **显示层**：图形 LCD，GBK 中文菜单，`disp_string`/`disp_uint4/5/2`/`disp_fixed_1dec` 渲染。
- **输入层**：旋转编码器（EINT1/EINT2）递增/递减 `edit_value`，按键（EINT3）。
- **菜单流**：
  - 频率（50/60Hz）→ 运行时间（本次/累计）→ 密码/初始参数设置 → **输出设定值编辑**（`X.X`，编码器调，10~1000）→ 运行模式（`恒压/恒流/开环`）→ 运行/停机。
- **输出换算**：`设定值 × 增益 / 1000` 得到实际输出量；增益按 `gain_sel`（模式）二选一。
- **I2C 同步**：每 ~16 轮把 4 组参数写往 I2C 器件 0xA6（地址 0x53，寄存器 0x97/98…）。
- **看门狗/超时**：屏幕超时 5000 计满则关闭 LCD 控制线。

下一步最有价值的动作是 **逆 UART3 "SINEP0WER" 协议**（§7.3）——它很可能是上位机/串口控制这台电源的通道，能直接把菜单里这些变量（频率/电压/运行状态）和外部命令对应起来。

## 9. 本会话确证：Modbus 寄存器 ↔ 状态机变量映射（2026-08-20 增补）

> 完整寄存器表见 `uart3_protocol.md` §4 / `PROGRESS_2026-08-20.md` §3。此处只列与状态机/输出相关的关键绑定。

| Modbus reg | RAM | 状态机角色 |
|---|---|---|
| 1 | 0x10001634 | **gain_sel** 模式（0/1/2=恒压/恒流/开环，§2 运行模式小表指针） |
| 2/3 | 0x1000163C/38 | **gain_a / gain_b**（§2 编辑换算 `×增益/1000`） |
| 11 | 0x10001655 | **sub_state**（0=正常/1=复制/2=编码器编辑） |
| 22 | 0x100016DE | 菜单第9项设定（编码器 0..60，芯片参数，内部不消费） |
| 23 | 0x10001710 | **cfg_1710** 参数组选择 1..4 |
| 24/25 | 读 0x1000170E/0F / 写 0x10001717/18 | 活动增益对（闭环用）/ 组4槽 |
| 40 | 读 0x100015A8 / 写 0x10001788 | **读=ADC ch5 测量**；**写=src_value 远程源值**（sub_state==0 显示/拷贝） |
| 47 | 0x100016FF | slave_addr |
| 51-55 | 0x10001698/A0/A8/B0/B8 | **ADC 各通道标定除数**（ch2/1/0/3/4） |
| 61 | 0x1000165C | **远程输出使能** → P0.20 |
| 62 | 0x10001660 | **输出下限系数**（FUN_0000e9ac 0x10002004=180-值） |

**状态机编辑换算确认**（§2 子状态 0）：
`out_scaled(0x10001774) = src_value(0x10001788) × 增益 / 1000`；`0x100015A8 = src_value`。
src_value 的唯一写入点是 **Modbus reg40 写 handler**（≤1000，见 PROGRESS §4i）；它是**易失运行时值**（不在 61 组同步表、load_config 不读回 → 上电恒 0）。state_machine 把 src_value 拷贝进 `0x100015A8`（reg40 读回源）→ **reg40 读写不对称的实质 = 远程注入值回显**：写后读回注入值；未写时 0x100015A8 由 ADC ch5 采样（FUN_00001fbc）填充 = 实测值。0x100015B4 是共享"输出参考"，ADC 链与 state_machine 双写，主循环执行序决定最终值。

**写多 0x10 旁路警告**：0x10 写多路径的落点与写单不同（reg40→0x100015A8 直写测量、reg24/25→活动对、reg27-32 等→scratch），**不要用 0x10 设置参数**（见 PROGRESS §4d）。
