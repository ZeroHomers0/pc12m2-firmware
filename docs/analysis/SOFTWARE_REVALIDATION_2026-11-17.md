## 真实差异与验证器修复

本批修复十二相 main() 的 EINT 初始化调用顺序：原 BIN 0x600→0x604→0x608 对应 EINT1→EINT2→EINT3；源码曾为1→3→2。单函数终态无法发现顺序颠倒，新连续 main 验证修复前在第14个调用报 MAIN_CALL_DIFF，修复后通过。修复前日志及基线哈希另存 eint_init_order_before.*。

通信测试原先可把双方相同的 Unicorn 异常转成成功结果，现改为拒绝，并新增异常注入反证。所有新增有界调用检查正常返回；外设永久未就绪记 WAIT_PERIPHERAL，不能充当成功返回。FIO 写迹改用实际执行 STR 指令观察，避免已知 MEM_WRITE hook 假执行；观察范围内遇未支持 STM 明确拒绝。

## 替身、观察边界与失败处理

EEPROM链在字节收发接口建外部介质模型，位级协议由独立768例交叉验证；main模型提供ADC/时钟/UART就绪、GPIO及成功认证响应，跳显示叶函数与纯等待。主循环节拍按tick_ready请求驱动，不把仿真指令数当作2ms实时时间。认证成功响应只服务main链，不作为永久放行与原厂认证算法等价的证据。

显示叶函数替身记录调用和参数；完整像素/GPIO渲染仍由官方显示专项验证。MMIO采用受控RAM/局部就绪位模型，未实现完整NVIC、W1C、GPIO电气、DMA/总线竞争或全周期调度。抢占仅列出的8个窗口。延时加速只用于已核对的空转内层，不用宽泛mask掩盖业务差异。

曾尝试全地址 MEM_READ hook 后发生Thumb异常跳转；缩到目标MMIO区间后消失，归为 OBSERVATION_ERROR，不作为源码缺陷。历史tmp状态机探针有宽泛延时mask及seed覆盖屏号风险，不纳入本批验收证据。
