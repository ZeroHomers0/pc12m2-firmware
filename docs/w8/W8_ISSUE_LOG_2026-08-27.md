## 问题 1：SWD 连不上（08-24，阻塞阶段 0 备份）

**现象**：J-Link Commander / J-Flash 均 `Could not connect to the target device`。

**排查（逐项排除）**：速率 10/100/400/4000 kHz 一致失败；接口名、命令行参数、复位类型、SWDIO/SWCLK 对调、供电、VTref=3.3V、接线均正常 → 全部排除。

**初判错误**：误认 SWDIO/SWCLK=P0.27/P0.28（PINSEL1）；因编译器生成 `load 基址+偏移`、单寄存器绝对地址不在二进制里，用"搜索地址字节"数不出 PINSEL3 → 误报 PINSEL 全 0。

**根因（修正定论）**：**固件初始化复用调试脚**——`adc_init()` 把 **P1.30(SWDIO) 复用为 AD0.4（Uf 反馈）**、`uart3_init()` 把 **P1.29(SWCLK) 用作 RS485 DE/RE**，两者在 `main()` 复位后立刻执行。原厂固件与重编固件一致 → SWD 连不上是**设计冲突，非 J-Link 硬件问题**。CRP=`0xFFFFFFFF` 无保护。

**解决**：加一根 nRESET 走 connect-under-reset，或走 ISP（UART0 + P2.10 拉低）。
**详细记录**：`W8_JLINK_DEBUG_2026-08-24.md`。

## 问题 3：ISP 备份与烧录（08-26）

**成功**：COM7 识别 LPC1765（Part ID `0x26013733`、Boot ROM 2.4），整片擦除成功。

**发现问题 A——板上有 CRP 读保护**：读 `0x2F0..0x30F` 返回 `security violation in device`。仓库备份文件 `0x2FC=0xFFFFFFFF` **不能推断板内当前状态**。有可信备份 + 用户授权 → 整片擦除。

**发现问题 B——9600 bps 串口写 256 KiB HEX 卡死**：长时间无进度、USB-TTL 灯不闪，等超 1 小时后终止 → **判定烧写未完成、不可用**（界面在运行 ≠ 烧写成功）。

**解决**：ISP 擦除后 SWD 可稳定连接 → 转 **J-Link SWD 写回金标准 `LPC1765.bin`**（写 98304 B / 12.9 s，`verifybin` 全镜像成功）。再验证原固件运行时 SWD 也曾直连成功（PC=0x1FAC），按指令二次整片擦除（5.6 s）。

**坑**：擦除后屏幕仍显示字符 = LCD 保持画面，不是 Flash 未擦除；以 Flash 读回 / `0x2FC` 读数为准。
**详细记录**：`W8_ISP_FLASH_2026-08-26.md`。

## 问题 4：自编译固件 CRP 地址布局冲突（08-26，烧写前拦截）

**发现**：`firmware.bin` 偏移 `0x2FC` = `0x721A2255`（落在 `wd_feed()` 指令中），不是无保护值 `0xFFFFFFFF`。直接烧写可能启用非预期读保护；只改 4 字节会破坏 `wd_feed()`。

**解决（三处 CRP 布局修复）**：
1. `startup.s` 新增 `.crp` 段发射 `0xFFFFFFFF`；
2. `lpc1765.ld` 固定 `.crp` 到 `0x2FC..0x2FF`（`.text` 从 0x300 起）；
3. `build.sh` objcopy 加 `--gap-fill 0xFF`。

修复后：`Reset_Handler=0x300`、`wd_feed=0x528`。**四道硬门槛全过**（0x2FC=FF、向量校验和、离线 11/11、A/B 全 PASS）。

## 问题 5：SWD 烧写后 MEMMAP 向量重映射坑（08-26）

**现象**：烧写后 `mem32 0x0` 读到 `10001FFC / 1FFF0081 / 全 0`，疑似"扇区 0 未擦净"。

**根因**：J-Link reset & halt 把核心停在 Boot ROM，`MEMMAP=0`，地址 0 映射的是 **Boot ROM 向量表**，不是 Flash。

**解决**：读真实 Flash 前先 `w4 0x400FC040, 1`（MEMMAP=1）。`verifybin` 走 flash loader 直读真实 Flash，不受影响。

**烧写结果**：erase(2.6 s)→loadbin(0.4 s)→verifybin 成功。板上确认：栈顶 `0x100029C8`、复位向量 `0x300`、向量校验字 `0xEFFFC2B6`、**CRP=`0xFFFFFFFF`**。
**详细记录**：`W8_POST_FLASH_2026-08-26.md`。

## 上电冒烟后——实测抓出的 4 个固件 bug（按发现顺序）

### 问题 7：认证锁机（c889a6b，调试专用）

**发现**：主循环可能被防抄板认证锁机（`auth_challenge`/`auth_retry` 失败 → `0x10000750=0` → 锁机屏死循环）。

**解决**：`main()` 在 `auth_retry()` 后强制 `*DAT_00000750=1`，跳过锁机分支进入主循环。

**2026-08-27 决定（抄板）**：**防抄板认证永久放行、不再启用**。强制放行为最终方案，注释同步更新（`bc4cbc4`）。`auth_challenge()/auth_retry()` 调用保留（保持原厂语义、A/B 等价性），结果被强制覆盖为放行。

### 问题 8：ADC wait_done 指针算术坑（79147cc）——闪屏+按键死同根因

**现象**：LCD 闪屏 + 按键全死。

**根因**：`adc0_wait_done()` 写 `g_adc + 4`，g_adc 是 `volatile uint32_t*`，`+4` 编译成 **+16 字节** → 读 **AD0DR0(0x40034010, ch0 专属)** 而非 **AD0GDR(0x40034004, 全局 DONE)**。转换非 ch0 通道时 DONE 永不置位 → 死循环 → 主循环挂死 → **WDT 复位循环（~1.6 s 一次）**，两症状同根因。

**修复**：`(uint)g_adc + 4` 先转整数做字节偏移。回归：`test_adc_wait_done_equivalence.py`（同时给 AD0GDR/AD0DR0 播不同结果，错读立即 FAIL）。
**相关记忆**：[[adc-wait-done-pointer-arithmetic-bug]]。

### 问题 9：input_scan FIO 指针元素偏移（572dcb4）——背光不亮+菜单死

**现象**：背光不亮 + 菜单无法操作。

**根因**：`DAT_00001974(uint32_t*) +0x34/0x14/0x74` 按元素偏移编译成 `+0xd0/0x50/0x1d0` → 读到 FIO 无效地址 → 编码器/按钮扫描永不触发 → key 恒 0 → 状态机 key>0 背光分支永不执行。

**修复**：`(uint32_t)DAT_00001974 + 0xNN` 字节偏移（保留 `gpio_inputs_dir_init` 元素索引）。回归：`test_input_scan_equivalence.py`（512 例 + 5 个按键事件定向）。

### 问题 10：case1 三分支 FAULT 门控（a77d38f）——首页上下键无效（根因 1）

**现象**：case1 首页"输入信号"上下键无效。

**根因**：三分支曾被 C 复刻错误嵌套进 `FAULT==0` else → 缺相参数开启 → FAULT 置位 → **上下键永不执行**。

**修复**：三分支移出 FAULT 门控（`07_state_machine.c:564-590`）。A/B 验证 + **板上字节比对**：`0x510e cbnz r3(FAULT), 0x5152`，与编译产物一致。

### 问题 11：DISP_SEL=控制方式（根因 2，原厂设计，非 bug）

**发现**：`DISP_SEL(0x10001655)` = **控制方式**（0 通讯 / 1 本地 / 2 定值），**只有"定值"分支处理 UP/DOWN 调 MANUAL**（原厂 0x52FA-0x542C + 操作手册第 77 行确认）。当前 EEPROM=1（本地）→ 首页显示 TARGET=0、上下键无效。

**残留验证**：DISP_SEL=0x01、影子=0x01。**在线 JLink 写 RAM 无法持久化**（ClrRESET 后 `load_config` 用 EEPROM 覆盖 live），须走面板菜单切"定值"。

**✅ 已验证（2026-08-27 实机）**：SET → 密码 UP×3+DOWN×3 → 基本参数设置 → 控制方式 → UP 切"定值" → SET。首页显示 50.0%，**上下键每按 ±0.1%、长按连续、断电保存，均符合预期**。
**详细记录**：`W8_DISP_SEL_FIX_2026-08-27.md`。**相关记忆**：[[disp-sel-control-mode]]。
