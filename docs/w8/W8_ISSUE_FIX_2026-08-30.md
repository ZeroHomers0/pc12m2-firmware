## 问题1：保护参数菜单（case3/case4）编辑态选中值不闪烁

**现象**
基本参数设置屏（MENU==3）选中一行按 SET 进入编辑态后，冒号后的值应闪烁（原固件行为），
重编译固件不闪烁；同屏 case4（另一组参数页）同样不闪烁。

**根因**
反编译源码渲染分支缺原 BIN 两块逻辑，缺一块即丢失闪烁：

1. **TIMEOUT3 超时擦除块（case3：原 BIN 0x5F74–0x60FE；case4：0x85C4–0x874E）**：
   `TIMEOUT3 > 0x1F4` 时回绕为 0，并按当前项 `MENU2` 用空格串擦除该值列
   （case3：item0-4 数值用 4 空格 0x5B38、item5-9 文字用 5 空格 0x6474、item0xa 用 3 空格 0x647C；
    case4：word 项用窄串 0x7E6C、byte 项值==0 用宽串 0x6474）。
2. **软起时间自动置 1 块（原 BIN 0x7BE2–0x7BF4）**：恒压/恒流（`CTRL_MODE<2`）且软起
   时间 `b4c` 未配置时自动置 1。

闪烁机制 = 上面两块与已有逻辑交替：`TIMEOUT3==0xFB` 整页重绘（当前项反显高亮 attr=1）→
`TIMEOUT3>0x1F4` 擦除当前值列（值消失）→ 循环，周期约 501 帧。反编译只译出前者，擦除块
丢失 → 只有反显、值不消失 → 观感为"不闪烁"。另：重绘时高亮 attr 曾误写死为 1（所有项同时
高亮），应仅当前项高亮。

**修复方法**
`firmware/src/07_state_machine.c`：
- case3 补回两块逻辑（`TIMEOUT3>0x1F4` 回绕 + 按 MENU2 空格擦除；`CTRL_MODE<2 && b4c==0`
  时 `b4c=1`），擦除串地址与原 BIN 字面量一致。
- case4 补回擦除块（窄串 0x7E6C / 宽串 0x6474，word 项值==0 用宽串）。
- 整页重绘高亮 attr 改为 `(*MENU2 == N) ? 1 : 0`（仅当前项反显）。
- case3 item4 行号与地址修正（值列位置对齐原 BIN）。

**验证**
A/B 执行级等价全 PASS（16 模块含 STATE_MACHINE_MATRIX 115 场景）；离线回归 14/14。

## 问题2：恢复出厂设置只显示"M"

**现象**
菜单进入恢复出厂设置确认页时，屏幕上只显示一个字符"M"，正确的显示应为"密码:------"类
提示。

**根因**
`disp_string` 第一参数（字符串地址）被反编译成 `0x6AA0`。原 BIN 0x6712 是
`ldr r0, [0x6AA0]`——从字面量池**取 0x6AA0 处存的值 0x4D9C**，反编译误当成"取 0x6AA0 处
的指令字节"。0x6AA0 处 4 字节 = `9C 4D 00 00`，以该地址作字符串起点首字节 0x4D='M'，
故只显示"M"。

**修复方法**
`firmware/src/07_state_machine.c`：`disp_string((int)0x6aa0, 1, 0, 0)` →
`disp_string((int)0x4d9c, 1, 0, 0)`（0x4D9C = "  密码:------"）。

**验证**
A/B 执行级等价全 PASS；字面量池 0x6AA0→0x4D9C 与原 BIN 一致。

## 问题3：Modbus 读寄存器 0x1001 返回错误（大端字节序错）

**现象**
Modbus 0x1001（控制方式）等寄存器读写值错误，多寄存器/单寄存器指令均受影响。

**根因**
Modbus RTU 帧内 16 位数据/数量字段是大端序（高位字节在前），反编译把拼接方向写反成
小端：`frame[4] | (frame[5] << 8)`；原 BIN 是 `(frame[4] << 8) | frame[5]`。共 4 处。

**修复方法**
`firmware/src/08_modbus_dispatch.c` 4 处改为大端拼接（各附原 BIN 地址注释）：
- 0x06 写单寄存器数据：`(frame[4] << 8) | frame[5]`（原 BIN 0xB798）
- 0x10 写多寄存器数量：`(frame[4] << 8) | frame[5]`（原 BIN 0xE202）
- 0x10 写多寄存器数据逐条：`(frame[7+i*2] << 8) | frame[8+i*2]`（原 BIN 0xE2C2）
- 0x03 读保持寄存器数量：`(frame[4] << 8) | frame[5]`（原 BIN 0xE408）

**验证**
`test/emulation/test_modbus_dispatch_execution.py` 全 PASS；A/B MODBUS_REGS 模块全 PASS。

## 问题4：PID 参数设置按键无法切换三级菜单

**现象**
PID 参数设置菜单（MENU==7）中按键无法切换三级菜单（MENU3 层级）。

**根因**
**原厂设计，非反编译回归**。A/B 执行级验证：PID 菜单 MENU2 导航门控 16 场景（不同
pidx/MENU2/MENU3 × UP/DOWN/SET 键），BIN 与 ELF 的 MENU2 终值逐项一致——重编译固件
与原固件在按键处理上行为相同，三级菜单切换限制为原程序固有逻辑（结合操作手册确认）。

**修复方法**
无代码改动。

**验证**
A/B：PID 菜单 16 场景 MENU2 终值 BIN=ELF 全一致。（GPIO 写迹长度差异为 Unicorn
mem-hook 已知伪影，非执行差异，见 `verify_firmware_equivalence.py` 说明。）

## 问题5：控制方式本地/定值/通讯应互斥

**现象**
基本参数设置→控制方式（DISP_SEL，0/通讯 1/本地 2/定值）编辑时按 UP，到上限后**环绕跳回
另一模式**，三种模式不互斥（定值按 UP 会跳回通讯，控制方式在三态间跳变）。

**根因**
case3 编辑 switch 增量分支 items 10-14（DISP_SEL/b56/ESTOP/FEEDBACK/INPUT_SEL）被反编译
成"超上限环绕到 0"：`if (*X > max) *X = 0`。原 BIN（0x6DF0–0x6EFA 反汇编）是**钳位在
上限**：item10 DISP_SEL `++ ; cmp #2 ; ble ; movs #2`（钳 2）、item11 钳 1、item12 钳 2、
item13 钳 1、item14 钳 1。item0 CTRL_MODE 例外：BIN 双向环绕（C 码原本就对，保持环绕）。

**修复方法**
`firmware/src/07_state_machine.c` case3 编辑增量 5 行改钳位（item0 保持环绕）：

```c
case 10: (*DISP_SEL)++;  if (*DISP_SEL > 2) *DISP_SEL = 2; break;   /* BIN 钳位 */
case 11: (*b56)++;       if (*b56 > 1) *b56 = 1; break;              /* BIN 钳位 */
case 12: (*ESTOP)++;     if (*ESTOP > 2) *ESTOP = 2; break;          /* BIN 钳位 */
case 13: (*FEEDBACK)++;  if (*FEEDBACK > 1) *FEEDBACK = 1; break;    /* BIN 钳位 */
case 14: (*INPUT_SEL)++; if (*INPUT_SEL > 1) *INPUT_SEL = 1; break;  /* BIN 钳位 */
```

**验证**
BIN 0x6DF0–0x6EFA 反汇编证据 + 新增 `test/emulation/test_case3_edit_equivalence.py`
256 用例（case3 全 16 项 × 边界值 × 4 键 2/3/0x16/0x21）A/B 全绿。注意 A/B 播种顺序坑：
`_seed_display_items` 会把 ESTOP/FEEDBACK/INPUT_SEL 播成 1/0/0，目标项须在标准播种之后再
覆盖，否则假一致。

## 问题6：本地模式无法设定值 + 复位按钮应显示"重启"

### 6a. 本地模式启动停止可操作但无法设定值

**现象**
控制方式=本地（DISP_SEL==1）时，首页启动/停止可操作，但输入信号（给定值）无法用上下键
设定。

**根因**
**原厂设计**。DISP_SEL 三分支（原 BIN 0x52FA–0x542C）只有 `DISP_SEL==2`（定值）分支处理
key==2/3（UP/DOWN）增减 MANUAL(0x100015D8)；本地/通讯分支不处理按键。操作手册同步确认：
"当定值闪烁时按 SET 键，给定由显示屏 UP/DOWN 增大或减小"。详见
`W8_DISP_SEL_FIX_2026-08-27.md`。

**修复方法**
无代码改动。用户须在基本参数设置→控制方式切到"定值(2)"后，首页上下键才可设定输入信号。

### 6b. 复位按钮应显示"重启"字样（新版坐标错位）

**现象**
外部复位键（P1.17 短接触发，去抖函数 `debounce_p117`）按下后，原固件流程显示"复位"随后
"重启"；新版把这两个字符串画到了错误坐标（显示在屏外角落），观感为没有"重启"字样。

**根因**
复位流程两处 `disp_string` 坐标被反编译成 `(0, 0, 0)`。原 BIN：
- 0x4EF2–0x4EF6 `movs r3,#0; movs r2,#0xa; movs r1,#3; adr r0→"复位"(0x522C); bl disp_string`
  → 行 3、列 0xa、属性 0
- 0x4F3C–0x4F40 同上 → `"重启"(0x523C)` 行 3、列 0xa、属性 0

同函数另一处复位/故障停机流程（line 1803/1806）坐标原本正确 (3,0xa,0)，两处应一致。

**修复方法**
`firmware/src/07_state_machine.c` 复位流程两处坐标 `(0,0,0)` → `(3, 0xa, 0)`：
```c
disp_string((int)0x522c, 3, 0xa, 0);   /* BIN 0x4EF6：复位(行3,列0xa) */
disp_string((int)0x523c, 3, 0xa, 0);   /* BIN 0x4F40：重启(行3,列0xa) */
```

**验证**
编译产物反汇编：ELF 0x4D08–16 / 0x4D50–58 与 BIN 0x4EF2–96 / 0x4F3C–40 参数一致
（r1=3, r2=0xa, r3=0）。分段 A/B（复位段入口 → 第一次 disp_string → 延时 → 第二次
disp_string → 延时 → 死循环）：BIN 与 ELF 均调用 `disp_string("复位",3,10,0)` →
`disp_string("重启",3,10,0)`，复位副作用 FAULT=0 / RUN=0 / STOP_PEND=1 / STOP_REQ=0 一致，
且两版均到达死循环（BIN 0x4F88 / ELF 0x4D96）。
