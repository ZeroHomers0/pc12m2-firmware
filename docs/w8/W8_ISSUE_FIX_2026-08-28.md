## 问题1：三级菜单（基本参数屏）编辑态选中值不闪烁

**现象**
MENU==3（基本参数屏，case3）选中一行按 SET 进入编辑态后，冒号后的值应闪烁以指示
"该值正在编辑"（原固件行为），重编译固件不闪烁。

**根因**
反编译源码的 case3 渲染分支独缺原 BIN 中两块逻辑，缺一块即丢失闪烁：

1. **TIMEOUT3 超时擦除块（原 BIN 0x7A32–0x7BD8）**：`TIMEOUT3 > 0x1F4` 时回绕为 0，
   并按当前项 `MENU2` 用空格串擦除该值列（16 个 item 各有专用擦除串，item4/5 依
   V_RANGE/A_RANGE 是否顶限位选宽/窄串）。
2. **软起时间自动置 1 块（原 BIN 0x7BE2–0x7BF4）**：恒压/恒流（`CTRL_MODE<2`）且
   软起时间 `b4c` 未配置时自动置 1。

闪烁机制 = 上面两块与已有逻辑交替：`TIMEOUT3==0xFB` 时整页重绘（当前项反显高亮）→
`TIMEOUT3>0x1F4` 时擦除当前值列（值消失）→ 循环，周期约 501 帧。反编译只译出前者，
擦除块丢失 → 只有反显、值不消失 → 观感为"不闪烁"。

**解决方法**
`firmware/src/07_state_machine.c`（约 line 1002–1036）补回两块逻辑：`TIMEOUT3>0x1F4`
回绕 + 16 项空格擦除（含 item4/5 限位分支），以及 `CTRL_MODE<2 && b4c==0` 时 `b4c=1`。
擦除串地址：0x6474=5 空格（item0/10..14）、0x7068=4 空格（item1..7）、0x647C=3 空格
（item8/9/15），与原 BIN 字面量一致。

**验证**
- 构建通过：`text 62228 / data 3000 / bss 2188`。
- A/B 执行级等价验证（原 BIN ↔ 重编译固件）16 模块全 PASS，含 `STATE_MACHINE_MATRIX
  115 场景`、`OUTPUT_STAGE_MATRIX 144`、`MODBUS_REGS`、`CLOSED_LOOP 6` 等。
- 离线回归 `run_tests.py` 14/14 PASS。

## 问题2：运行模式"恒流"时恒流 LED（LCD18）不亮

**现象**
菜单 1.基本参数设置 → 运行模式：开环时 LCD18/LCD20 都不亮（符合预期）、恒压时
LCD20 亮（符合预期）、恒流时按理 LCD18（P1.21，恒流 LED18B）应亮，实际不亮。

**根因分析（结论：原程序固有行为，非反编译回归）**
case3 item0（运行模式）渲染逻辑，原 BIN 反汇编（0x7460–0x7584 两套三态）与反编译
源码逐指令一致：

| 模式 | P1.20（恒压 LED20A） | P1.21（恒流 LED18B） |
|---|---|---|
| 开环 | 高 | 低 |
| 恒压 | 低 | 高 |
| 恒流 | 低 | 低 |

即**恒流时 P1.21 为低 = 原程序固有行为**（代码级一致），不是重编译引入的回归。
硬件链路存疑：按"低电平点亮"推断，恒流模式 P1.21 两次该亮未亮，需实机万用表测
P1.20/P1.21 电平与 LED18B 两端确认（P1.21 是否被拉低/驱动能力/限流电阻）。

**顺带解决：主屏刷新开环分支 LED 错译**
排查中另发现主屏刷新（原 BIN 0x4E30）开环分支，反编译把 `fio1_pin20_ctrl(1)`（P1.20
置高）**误译成 `(0)`**，已还原（`firmware/src/07_state_machine.c` line 471：
`*DISP_MODE = 1; fio1_pin20_ctrl(1); fio1_pin21_ctrl(0);`）。objdump 确认新固件对应处
生成 `movs r0,#1; bl fio1_pin20_ctrl`。

**验证**
- A/B 执行级等价验证全 PASS（16 模块，同问题1）。
- case3 渲染区段逐指令一致（0x7460–0x7584）。
- 错译修复后主屏开环刷新生成 `r0=1` 调用，与字面量池 0x5210→0x10001634（CTRL_MODE）、
  0x5214→0x100015CD（DISP_MODE）一致。
