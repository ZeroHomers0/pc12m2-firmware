## 3. 查表

### 3.1 CRC16 双表（flash）★
- 位置：表 A `0x00011034`、表 B `0x00011134`（各 256 字节，u16 项）
- 函数：`crc16`（0xAF64）——**大端变体**：
  ```c
  uint crc16(byte *buf, uint len) {
    uint hi = 0xff, lo = 0xff;              // init = 0xFFFF
    while (len--) {
      u = *buf ^ lo;
      lo = tblA[u] ^ hi;                     // tblA = @0x11034
      hi = tblB[u];                          // tblB = @0x11134
      buf++;
    }
    return lo | hi << 8;                     // 高字节在前
  }
  ```
- 表 A 首 8 项：`0xC100, 0x4081, 0xC001, 0x4180, 0xC001, 0x4180, 0xC100, 0x4081`
- 表 B 首 8 项：`0xC000, 0x01C1, 0x03C3, 0xC202, 0x06C6, 0xC707, 0xC505, 0x04C4`
- 指针字：flash `0x0000B05C` → 0x11034、`0x0000B060` → 0x11134

### 3.2 波特率表（SRAM 0x100017BC）★已定位（2026-08-21）
- 表：`0x100017BC`，**8 × u32**（波特率档 0..7），**存波特率数值本身**（非分频系数）
- **初始值 = `[2400, 4800, 9600, 14400, 19200, 38400, 57600, 115200]`**
  —— 已通过 IAR 压缩 `.data` 流解压精确定位（`tools/generation/extract_ram_data_image.py`，d 精确收敛 0x213C、s 精确止于 0x12AC5，零越界）
- 指针：flash `0x0000B028` → 0x100017BC（仅 uart3_init 读取，6 处）✓ 解压镜像精确命中
- 使用（`uart3_init` 0xAC24）：
  `分频 = PCLK(0x16E360=1500000) / (baud[baud_idx] × factor / 1000)`，
  其中 factor 按档：idx 0-2=0x3BB、3=0x3B6、4=0x3B1、5=0x3AA、6=0x39D、7=0x393
- 分频结果 ≈ `654, 327, 163, 109, 82, 41, 28, 14` → DLL/DLM（UART 实际波特率由 UART_PCLK/(16×DLL) 决定）
- ⚠ 旧标修正：此前误判"表存分频系数 1309/654/…"；实为**波特率数值**，故 flash u32 全盘扫描系数失败（`tools/locate_sram_mirrors.py` v1 结论作废）

## 7. W2 待办（精确初始值定位）— 全部落地（2026-08-21）

1. ✅ **波特率表初始值**：SRAM 0x100017BC = **`[2400,4800,9600,14400,19200,38400,57600,115200]`**（波特率数值）。
   IAR 压缩 `.data` 流已完整解压（`tools/generation/extract_ram_data_image.py`）：流 0x11254→0x10000000、len 0x213C，d 精确收敛、s 精确止于 0x12AC5、零越界；**解压算法关键**：重复循环 0x156 为 `bpl`（带符号）→ **重复次数 = r5+2**（非 r5+1，此为当初 step14 越界的根因）。
2. ✅ **PID 除数表 / 误差区间表镜像**：非 flash 查表，为**运行时立即数**（`12_closed_loop.c` closed_loop_integral 级联 if-else 赋值，0x10010CF4/0x10010F40 是运行期变量）→ 待办消除。
3. ✅ **触发序列表（mode1/mode2）**：非查表。TIMER1 ISR@0xFF6C = **LCD 12864 硬编码扫描**（disp_scan 行计数 0..0xF0，每 0x28 行一组逐段判断）；SCR 触发序列 = EINT3 每过零编程 TIMER2.MR0 + TIMER1 扫描 6 窗口×40 步（立即数）→ 待办消除。
4. ✅ **完整字符串池扫全**：`DATA_SEGMENT §2` 已含 GBK 全表（318 条菜单字符串 + LCD 映射区，见 §2）。补扫脚本（`tools/locate_sram_mirrors.py` §3）验证：高位区 0x36000-0x3FFF0 全 0xFF 空白、字符串集中于 0x2000-0x7200 与 0x12000-0x13000。GBK 判定误伤代码区（乱码）已废弃，以 §2 表为准。
5. ✅ **0x1000EDF4 保护标志位域、0x10001624 out_param 位域已确认**（2026-08-21 反编译确证，见 §6 表）。

### 附：IAR 压缩 .data 镜像机制（目标 B 需要复刻）
- **描述符表** @flash 0x11234（每 16 字节一条: src,dst,len,func），仅 2 条有效：
  1. `(0x11254, 0x10000000, 0x213C, 0x100)`：**压缩解压**（`__iar_copy_data` 风格，run-length+回退复制）→ SRAM .data
  2. `(0x12AC8, 0x1000213C, 0x88C, 0x164)`：**BSS 清零** → SRAM .bss（区域 0x1000213C-0x100029C8）
- **解压算法**（0x100-0x162 权威反汇编）：控制字节 → 低2位字面拷贝数（0 则读扩展字节）；高4位重复数（0 则读扩展）→ **字面拷贝 r4-1 字节**；**重复 r5+2 字节**（回退源 = dst-back，back = rb+(mid<<6)，mid=0xC 时 back = rb+(hi<<8)）
- 拷贝启动器 `startup_copy_ram@0xCC`：`adr r0,[0xF8]; ldm.w {r10,r11}`，r10=0x11234（描述符表）、r11=0x11254（流起点），循环遍历描述符调用 func
- CRC 表 A@0x11034、B@0x11134 紧邻描述符表（0x11134+0x100=0x11234）
